# Shared UI primitives

Import from `@/components/ui`. Components use the shared semantic CSS tokens and native controls. Keep business rules, API calls and route navigation in the consuming feature. No new dependency is required.

| Export                                  | Contract                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Button                                  | Native button props/ref; `variant` primary/secondary/quiet/danger; defaults to `type="button"`. Optional `leadingIcon`/`trailingIcon` slots are decorative and hidden from assistive technology: use noninteractive SVGs and keep a readable text label. `busy` disables activation and replaces the label with `busyLabel` (default Working…). Use an explicit submit/reset type inside forms. |
| TextField / SelectField / TextAreaField | Native props/ref plus required visible `label`, optional `hint` and `error`. Stable generated ID or caller-supplied ID; errors set aria-invalid and link descriptions. Select options are children. Preserve native required/type/autocomplete semantics.                                                                                                                                       |
| Checkbox                                | Native checkbox props/ref plus label/hint/error. Whole visible label is a touch target.                                                                                                                                                                                                                                                                                                         |
| Card                                    | Named section with title, optional eyebrow/description, children and optional `headingLevel` (2 or 3). Choose hierarchy for the page.                                                                                                                                                                                                                                                           |
| Notice                                  | `tone` info/success/warning/error, title and children. Visible severity words. Set `live` only for dynamic announcements; error uses alert, others status. Avoid redundant announcements.                                                                                                                                                                                                       |
| Badge                                   | Children and neutral/success/warning tone. Always include meaningful words.                                                                                                                                                                                                                                                                                                                     |
| Skeleton / LoadingState                 | Decorative text/block skeletons; LoadingState requires a meaningful status label. Mount/unmount with actual request state when integrations exist.                                                                                                                                                                                                                                              |
| EmptyState                              | Title, description, optional action. Provide a relevant next step.                                                                                                                                                                                                                                                                                                                              |
| Tabs                                    | Controlled value/onValueChange and items with unique stable id/label/content/optional disabled. Horizontal automatic activation with Left/Right/Home/End, wrapping and disabled skipping. Panels remain mounted but hidden, preserving input. Use for immediate local content; remote/expensive tabs need a separate manual-activation design.                                                  |
| Modal                                   | Controlled open/onOpenChange, title, optional description and children; kind dialog (default) or drawer. Native showModal/inert background, initial Close focus, explicit boundary Tab wrapping, Escape/visible Close, native trigger focus restoration and scroll-lock cleanup.                                                                                                                |

Modals must be opened from an existing focusable trigger that remains mounted. Keep one modal open at a time in application flows. The container supplies no implicit form, destructive action, backdrop-click dismissal or persistence. Actions request closure through the controlled callback; the parent must update `open`. Close is always available. This initial wrapper supports ordinary DOM controls; editor popovers, portals, shadow-DOM controls and more complex embedded widgets require integration-specific focus tests before use.

Client components must own event handlers/state. Fields do not choose validation rules: the preview demonstrates local validation/focus recovery only; consuming forms must integrate real server errors, pending state and business rules later. Never replace labels with placeholders. Required markers are visual; native required semantics remain available to assistive technology.
