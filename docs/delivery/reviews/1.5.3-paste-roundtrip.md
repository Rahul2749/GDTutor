## Result and demonstration

The [isolated editor](../../../experiments/question-editor/README.md) now opens **Check your pasted content** before inserting a clipboard transfer. **Paste source** opens the same workflow manually in each prompt/answer/explanation region. Choose explicit LaTeX, text with `\(…\)`, `\[…\]` or `$$…$$`, a limited Presentation MathML subset, or supported rich HTML. Inspect the normalized preview and repair unsupported source before insertion. Single-dollar currency stays ordinary text. Plain-text line breaks become explicit breaks.

Native editor copy/paste retains equation metadata in HTML and explicit delimiters in plain text. Conflicting equation metadata, duplicated renderer wrappers, unknown commands, unclosed delimiters, invalid structures, images/tables/objects and untrusted resource/event markup are blocked atomically. The current draft stays unchanged; source remains in the dialog until the user edits or cancels it. Browser textarea line endings normalize to LF; original captured bytes stay in the ignored intake folder.

Equation dialogs offer **Copy LaTeX** and **Copy MathML**. Clipboard failures show a manual-copy message. These actions expose source representations; they do not promise every Word/browser version accepts them.

## Evidence and compatibility limits

| Experiment | Observed result | Interpretation |
|---|---|---|
| Controlled browser text/LaTeX/basic MathML/rich HTML transfers | Editable equations retained in all six regions; Unicode, nested lists, correct answer and unrelated regions retained through save/reopen | Verified only for the recorded fixtures/configuration |
| Browser MathML copy → trusted paste → review → save/reopen | Fraction/root remain structured and editable | Browser round trip; not native Word interoperability |
| Native Word PUB-01 copy | Word 16.0.20430.20146 on Windows 10.0.26200 exposed 14 formats including MathML, HTML, RTF and text; raw payloads kept local | Actual native source evidence; [Word probe](../../reference/WORD-CLIPBOARD-PROBE.json) |
| Native Word → automated Chrome Control+V | Trusted paste event arrived with zero formats and zero text/HTML | Environment gap; no direct Word paste pass. [Native boundary probe](../../reference/WORD-TO-BROWSER-PROBE.json) |
| Captured Word HTML supplied to normalizer as a controlled fixture | Office math/VML/image content was explicitly blocked with repair guidance | Payload normalization test, not a successful native transfer |
| App-generated MathML replayed through a Windows clipboard broker into Word | Both HTML+plain and plain-MathML routes created one native OMath with numerator 2, denominator 3 and radicand 5 | Native structure verified for this replayed fixture. Direct browser-to-Word clipboard and full visual fidelity remain unverified. [Outbound probe](../../reference/WORD-OUTBOUND-PROBE.json) |
| Nine native DOCX equations converted to research MathML references | One accepted by the subset; eight require repair, including formatting/notation and strict-source gaps | Reference conversion only, not a DOCX importer or full-fidelity success |

The public-reference conversion uses the **locally installed Office stylesheet for research only**. Its bytes are not copied or adopted. The application never loads it or requires Office. It exposes why a tiny hand-written MathML subset is insufficient as a complete DOCX conversion strategy. Public PUB-02 contains legacy OLE objects; they were never activated, converted or counted as editable math.

Google Docs, Word Online/macOS, LibreOffice/WPS, PDF viewers, other browser engines, real mobile devices and assistive technologies remain unverified. Representative scripts and synthetic subject notation are not exhaustive language/subject certification. No native Word layout/render fidelity claim is made from structural XML alone. No DOCX artifact was authored or delivered; Word target documents existed only in memory and closed unsaved.

## Fallback needs for 1.5.4 review

1. Start with explicit LaTeX/visual entry and supported reviewed text/HTML; qualify MathML support by tested subset/configuration. Preserve repair diagnostics.
2. Make a separate reviewable **DOCX import** path part of the conversion decision if ordinary Word paste cannot deliver required equations. Compare a maintained open-source converter against the public and eventual teacher corpus; retain original/source diagnostics and map prompts/options/explanations before saving. No converter was selected or built here.
3. Keep image/PDF/OLE content explicitly non-editable until a teacher recreates it or a reviewed importer handles it. No automatic OCR or proprietary OLE execution.
4. Run actual teacher Word/browser copy and outbound re-entry trials before advertising those workflows. The controlled Word replay proves a useful representation, not the complete native clipboard boundary.
